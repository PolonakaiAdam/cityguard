CITYGUARD PROJEKT – EGYSZERŰ MAGYARÁZAT
======================================

Ez a fájl azért készült, hogy egy olyan ember is megértse a projektet,
akinek nincs programozói tapasztalata.


1. MI EZ A PROJEKT?
-------------------
A CityGuard egy hibabejelentő rendszer.

Egyszerűen mondva:
- a lakos be tud jelenteni egy problémát,
- az ügyintéző vagy admin látja a bejelentést,
- a státuszt át tudják állítani,
- lehet megjegyzést írni,
- a rendszer kezeli a profilokat, képeket és egyes kéréseket is.

Ilyen problémák lehetnek például:
- kátyú,
- szemét,
- közvilágítás hiba,
- rongálás,
- közlekedési probléma,
- egyéb önkormányzati gond.


2. KINEK KÉSZÜLT A RENDSZER?
----------------------------
A rendszer többféle felhasználót kezel.

1) Lakos
   - új bejelentést tud létrehozni,
   - látja a bejelentéseket,
   - látja és szerkeszti a saját profilját,
   - üzenetet vagy kérést tud küldeni.

2) Ügyintéző
   - látja a bejelentéseket,
   - kezeli a kéréseket,
   - tud státuszt módosítani,
   - tud megjegyzést írni.

3) Adminisztrátor
   - látja a bejelentéseket,
   - kezeli a felhasználókat,
   - törölhet dolgokat,
   - felügyeli a rendszert.

4) Önkormányzat
   - egy összesítő nézetet lát,
   - statisztikákat és listát lát a bejelentésekről,
   - inkább áttekintő szerepe van.


3. MI TÖRTÉNIK, AMIKOR VALAKI HASZNÁLJA?
----------------------------------------
A rendszer működését legegyszerűbben így lehet elképzelni:

1) A felhasználó megnyitja az oldalt.
2) Bejelentkezik.
3) A rendszer megnézi, hogy milyen szerepköre van.
4) Ennek alapján a megfelelő kezdőoldalt nyitja meg.
5) A felhasználó műveletet végez:
   - új bejelentést küld,
   - megnézi a listát,
   - módosít valamit,
   - képet tölt fel,
   - üzenetet küld.
6) A böngésző elküldi a kérést a megfelelő API fájlnak.
7) A PHP feldolgozza ezt.
8) Az adatbázisba mentés történik.
9) A rendszer visszaküld egy választ.
10) A felület frissül.

Röviden:
Böngésző -> API -> adatbázis -> válasz -> képernyő frissül.


4. A PROJEKT FŐ FUNKCIÓI
------------------------

A) Bejelentkezés és regisztráció
- új felhasználó létrehozása,
- belépés,
- kilépés,
- annak ellenőrzése, hogy ki van bejelentkezve.

B) Új bejelentés létrehozása
A lakos ki tud tölteni egy űrlapot:
- kategória,
- cím,
- leírás,
- helyszín,
- kép.

A hely megadható például:
- GPS alapján,
- térképes kijelöléssel.

C) Bejelentések listája
A rendszer ki tudja listázni az összes bejelentést.
Lehet látni például:
- címet,
- leírást,
- kategóriát,
- státuszt,
- képet,
- beküldőt,
- dátumot.

D) Státuszkezelés
A bejelentés állapota ilyen lehet:
- Új
- Folyamatban
- Megoldva
- Elutasítva

Ezeket főleg admin és ügyintéző tudja kezelni.

E) Megjegyzések
A bejelentésekhez hozzászólás vagy megjegyzés írható.
Ez segít a kommunikációban.

F) Képfeltöltés
Kétféle képkezelés is van:
- bizonyíték fotó a bejelentéshez,
- profilkép a felhasználóhoz.

G) Profilkezelés
A felhasználó tudja módosítani például:
- a nevét,
- email címét,
- jelszavát,
- profilképét.

H) Kérések és üzenetek
A felhasználó tud küldeni:
- sima üzenetet,
- email csere kérést,
- jelszó-visszaállítási kérést.

Ezeket a kezelő oldalon admin vagy ügyintéző láthatja és feldolgozhatja.

I) Térkép
A projektben külön térképes oldal is van.
Ez arra való, hogy a bejelentések helye könnyebben áttekinthető legyen.

J) Önkormányzati áttekintés
Az önkormányzati szerepkör egy külön dashboardot lát.
Ez egy összesítő oldal, nem elsősorban szerkesztésre szolgál.


5. SZEREPKÖR SZERINT KI MIT LÁT?
--------------------------------
A projekt egyik fontos része, hogy nem mindenki ugyanazt látja.

A leegyszerűsített logika nagyjából ez:
- Lakos -> Új bejelentés, Bejelentések, Profil
- Ügyintéző -> Bejelentések, Profil, Kérések
- Admin -> Bejelentések, Profil, Admin felület
- Önkormányzat -> Önkormányzati áttekintés, Profil

A kezdőoldal is szerepkör szerint változik:
- Lakos -> Új bejelentés
- Ügyintéző -> Bejelentések
- Admin -> Bejelentések
- Önkormányzat -> Önkormányzati áttekintés

Ez azért jó, mert a felhasználó rögtön arra az oldalra kerül,
amelyik neki a legfontosabb.


6. HOGYAN NÉZ KI A PROJEKT BELÜLRŐL?
------------------------------------
A projekt több fő részből áll.

A) public/
Ez a látható rész.
A böngésző innen nyitja meg az oldalt.

Fontos fájlok:
- public/index.php
  Ez a főoldal.
  Itt jelenik meg a felület.

- public/map.php
  Ez a térképes oldal.

- public/change_email.php
  Email-csere visszaigazolás oldala.

- public/reset_password.php
  Jelszó-visszaállítás oldala.

- public/assets/css/style.css
  Az oldal kinézete.

- public/assets/js/app.js
  A fő JavaScript logika.
  Ez mozgatja a gombokat, nézeteket, űrlapokat, kéréseket.

- public/assets/js/map.js
  A térképpel kapcsolatos működés.

B) api/
Ez a háttérben dolgozó rész.
A böngésző ezekhez a fájlokhoz küld kéréseket.

Példák:
- auth_login.php -> belépés
- auth_register.php -> regisztráció
- auth_me.php -> ki van most bejelentkezve
- reports_create.php -> új bejelentés mentése
- reports_list.php -> bejelentések listázása
- reports_update_status.php -> státusz módosítása
- report_delete.php -> bejelentés törlése
- report_update.php -> bejelentés szerkesztése
- comments_create.php -> komment létrehozása
- comments_list.php -> kommentek betöltése
- upload_evidence.php -> bizonyíték kép feltöltése
- upload_profile_image.php -> profilkép feltöltése
- user_message.php -> felhasználói üzenet küldése
- admin_messages_list.php -> admin oldalon a kérések listája
- admin_user_update.php -> felhasználó módosítása
- admin_user_delete.php -> felhasználó törlése

C) app/
Ez a projekt közös motorja.
Itt vannak azok a fájlok, amiket sok más fájl használ.

Legfontosabbak:
- app/api.php
  Közös betöltő az API fájlokhoz.
  Olyan, mint egy központi induló csomag.

- app/bootstrap.php
  Elindítja az alkalmazás alap működését,
  például hibakezelést.

- app/helpers.php
  Általános segédfüggvények.
  Olyan kis újrahasznosítható eszközök,
  amelyeket sok helyen használ a rendszer.

- app/auth.php
  Bejelentkezés és jogosultság ellenőrzése.
  Megnézi, hogy a felhasználó belépett-e,
  és van-e joga valamit csinálni.

- app/db.php
  Adatbázis kapcsolat és tábla létrehozás.

- app/domain.php
  Közös szótár.
  Itt vannak például a szerepkörök és státuszok nevei.

- app/mailer.php
  Email küldéssel kapcsolatos logika.

D) config/
- config/config.php
  Itt vannak a beállítások,
  például az adatbázis adatai és az alap URL.

E) sql/
- sql/cityguard.sql
  Az adatbázis szerkezete.
  Megmondja, milyen táblák legyenek.

F) storage/
Ez inkább technikai háttérmappa.
Például naplófájlok vagy ideiglenes dolgok lehetnek itt.

G) uploads/
Itt tárolódnak a feltöltött képek.
Például:
- bizonyíték képek,
- profilképek.


7. MI AZ ADATBÁZIS SZEREPE?
---------------------------
Az adatbázis a projekt memóriája.
Itt maradnak meg az adatok akkor is, ha bezárod a böngészőt.

Fő táblák:

1) users
   A felhasználók adatai.
   Például:
   - név,
   - email,
   - jelszó,
   - szerepkör,
   - profilkép.

2) categories
   A bejelentés kategóriái.
   Például kátyú, szemét, egyéb.

3) reports
   A bejelentések fő táblája.
   Itt van maga a hibabejelentés.

4) report_comments
   A bejelentésekhez tartozó megjegyzések.

5) user_messages
   A felhasználók által küldött kérések és üzenetek.

6) email_change_requests
   Email-csere folyamatok tárolása.

7) password_resets
   Jelszó-visszaállítási adatok.

8) email_change_tokens
   Email-változtatás megerősítéséhez szükséges adatok.


8. HOGYAN LETT LEEGYSZERŰSÍTVE A KÓD?
--------------------------------------
A tiszta kód lényege nem az, hogy a kód rövidebb legyen,
hanem az, hogy könnyebb legyen olvasni és javítani.

Ebben a projektben a leegyszerűsítés lényege nagyjából ez:

A) Az ismétlődő dolgok közös helyre kerültek
Például:
- segédfüggvények egy helyre,
- szerepkör nevek egy helyre,
- státusz nevek egy helyre,
- API indulás egy helyre.

Ez azért jó, mert ha valamit módosítani kell,
nem sok fájlban kell keresni ugyanazt.

B) A szerepkör-logika külön lett kezelve
Nem össze-vissza van szétszórva, hogy ki mit láthat,
hanem külön szabály dönti el.

C) A kezdőoldal logika külön helyre került
Most már könnyebb megérteni, hogy:
- lakos miért az új bejelentéshez jut,
- admin miért a bejelentésekhez,
- önkormányzat miért az összesítőhöz.

D) A hibák kezelése rendezettebb lett
Van közös hibakezelés és logolás.
Ez segít, ha valami elromlik.

E) A fájlszerkezet átláthatóbb lett
A projekt külön mappákra van bontva:
- public = amit a felhasználó lát,
- api = háttérkérések,
- app = közös motor,
- config = beállítások,
- sql = adatbázis.

Ezt egy kezdő is könnyebben átlátja.

10. MI TÖRTÉNIK TÖRLÉSKOR?
--------------------------
Például amikor admin töröl egy bejelentést:

1) A gombra kattint a felhasználó.
2) A JavaScript meghívja a megfelelő API-t.
3) Az API ellenőrzi, hogy a felhasználó jogosult-e.
4) Ha igen, az adatbázisból törli a bejegyzést.
5) A rendszer visszajelez.
6) A lista újratöltődik.

Ha bármelyik rész hibás,
akár egy rossz fájlnév vagy rossz kérés miatt,
akkor jelenhet meg olyan hiba, mint például a "Hibás adatok".


11. MIÉRT JÓ EZ A SZERKEZET EGY NEM HOZZÁÉRTŐNEK IS?
----------------------------------------------------
Azért, mert könnyebb fejben szétválasztani a részeket.

Például:
- Ha a kinézet rossz -> valószínűleg CSS.
- Ha a gomb nem reagál -> valószínűleg JavaScript.
- Ha a mentés nem működik -> valószínűleg API vagy adatbázis.
- Ha a belépés hibás -> auth rész.
- Ha a jogosultság rossz -> szerepkör ellenőrzés.

Vagyis könnyebb megtalálni, hogy melyik rész mivel foglalkozik.


12. HOL KERESS, HA VALAMIT MÓDOSÍTANI AKARSZ?
---------------------------------------------

Ha ezt szeretnéd... -> itt érdemes keresni

- oldal kinézete -> public/assets/css/style.css
- gombok, nézetek, felület -> public/assets/js/app.js
- térkép -> public/assets/js/map.js és public/map.php
- főoldal felépítése -> public/index.php
- belépés/regisztráció -> api/auth_*.php + app/auth.php
- bejelentések -> api/reports_*.php
- kommentek -> api/comments_*.php
- képfeltöltés -> api/upload_*.php
- felhasználók kezelése -> api/admin_user_*.php
- üzenetek/kérések -> api/admin_messages_*.php és api/user_message*.php
- adatbázis -> app/db.php és sql/cityguard.sql
- általános segédek -> app/helpers.php
- szerepkörök és státuszok -> app/domain.php
- beállítások -> config/config.php


13. RÖVID ÖSSZEFOGLALÁS EGY MONDATBAN
-------------------------------------
A CityGuard egy több szerepkörös, térképes, képfeltöltős,
önkormányzati hibabejelentő rendszer, ahol a lakos bejelent,
a kezelő feldolgoz, az admin felügyel, az önkormányzat pedig áttekint.
